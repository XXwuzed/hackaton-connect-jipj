# Decisiones · Fase 1A

Fecha: 2026-10-08 (America/Guayaquil).

| Duda                                                                     | Decisión                                                                                                        | Motivo                                                                                                   |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| El schema anunciado por el prompt no estaba en el repositorio            | Se incorporó el archivo `schema (2).prisma` entregado por el usuario                                            | Es la fuente de verdad disponible.                                                                       |
| Un asesor registra canjes y dados en una tienda, pero `User` no la tenía | Se agregaron `User.storeId`, `User.store`, `Store.users` y el índice de `storeId`                               | La relación permite resolver la tienda del asesor en el servicio.                                        |
| Algunas claves foráneas del borrador carecían de índice propio           | Se añadieron índices a relaciones consultables de canjes, dados y asignaciones por zona                         | Evita búsquedas lentas por esas relaciones. No altera los datos ni las reglas del negocio.               |
| La fecha de aniversario del 29 de febrero no existe al año siguiente     | Se usa el 28 de febrero, al final del día de Guayaquil                                                          | Mantiene un año civil sin desbordar al 1 de marzo.                                                       |
| Puerto de PostgreSQL local                                               | `127.0.0.1:5432`                                                                                                | Permite desarrollo local sin exponer PostgreSQL a la red.                                                |
| Dependencias de compilación de Tailwind y TypeScript                     | Se usan `postcss`, `autoprefixer`, `@vitejs/plugin-react`, `typescript-eslint`, `@eslint/js` y tipos `@types/*` | Son herramientas necesarias para compilar el stack solicitado, no funciones del producto.                |
| Compatibilidad con Node 20                                               | Se fija pnpm 10; el pnpm 11 disponible en este equipo se usó para instalar y acepta `allowBuilds`               | pnpm 11 exige Node 22 o posterior. `onlyBuiltDependencies` conserva el permiso equivalente para pnpm 10. |
| Instantes del schema eran `TIMESTAMP` sin zona                           | Se añadió `@db.Timestamptz(3)` a todos los instantes; `redeemedDate` conserva `@db.Date`                        | El corte de días en Ecuador necesita instantes inequívocos.                                              |
| Restricciones numéricas y de formato descritas en comentarios del schema | La migración incorpora `CHECK` para cédula, puntos, margen, descuento, dados, cantidad y ajuste visual          | Prisma no representa esos límites en el archivo de schema.                                               |
| `argon2`, Leaflet y JWT aún no tienen código de uso en 1A                | Se instalarán cuando existan autenticación y zonas                                                              | Evita dependencias sin uso y mantiene `knip` útil.                                                       |
| Archivos de infraestructura previstos que todavía no tienen consumidores | Permanecen como stubs y se excluyen explícitamente de `knip` hasta la fase 2                                    | Conserva el árbol solicitado sin inventar rutas o reglas de negocio.                                     |
| La condición de dados ($10 o productos habilitados) sigue abierta        | No se implementa validación de negocio en 1A                                                                    | La pregunta del documento de contexto sigue pendiente.                                                   |
| Credenciales AWS temporales aportadas por el usuario                     | La API acepta `AWS_SESSION_TOKEN`; las credenciales quedan en `hackaton-backend/.env`, ignorado por Git         | STS necesita el token para firmar solicitudes. Los frontends no reciben secretos.                        |

El borrador de schema conserva los campos existentes. Cualquier regla de negocio no indicada aquí se deja para la siguiente fase.

## Fase 1B · 2026-10-08

| Tema                          | Decisión                                                                                                                | Motivo                                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Ruta del prompt `apps/api`    | Se usa `hackaton-backend/`, nombre real del monorepo                                                                    | No se reestructura una fase anterior.                                                                                         |
| Despliegue AWS                | Se suspende durante esta ejecución de 1B; requiere nueva orden explícita                                                | El usuario pidió no tocar AWS antes.                                                                                          |
| Datos base                    | `prisma/mock/fixtures/base.json` marcado `synthetic: true`; `seed.ts` acepta opcionalmente `prisma/mock/data/base.json` | No hay archivos de usuario en esa ruta; no se inventan datos reales.                                                          |
| Secretos del seed             | `SEED_ADMIN_PASSWORD` y `SEED_ADVISOR_PASSWORD` se leen del entorno, nunca del fixture                                  | La prueba manual necesita contraseñas, pero no deben versionarse.                                                             |
| Integraciones externas        | Claves de S3, Resend y reCAPTCHA son opcionales al arrancar; cada operación falla cerrada si falta su configuración     | La Fase 1B debe poder probar auth sin inventar credenciales externas.                                                         |
| Refresh stateless             | Cambiar contraseña no revoca un refresh anterior; logout solo borra cookies                                             | Es la limitación de la sesión stateless exigida por el prompt. Para invalidación inmediata se necesitaría estado server-side. |
| `mustChangePassword` y logout | Se permite borrar cookies aun sin sesión válida                                                                         | Cerrar sesión nunca debe quedar bloqueado.                                                                                    |
| Prueba en navegador           | Queda pendiente                                                                                                         | `agents/instructions_1.md` prohíbe abrir el navegador para probar; se prioriza esa restricción local.                         |
| Pruebas con PostgreSQL        | Se dejan pendientes por elección del usuario                                                                            | Este equipo no tiene Docker/PostgreSQL y el usuario prefirió no instalarlos.                                                  |

## Fases 2–5 · 2026-10-08

| Tema                           | Decisión                                                                                                                                               | Motivo                                                                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| Alcance por ejecución          | Se implementa código de fases 2–5 en un mismo turno, sin AWS                                                                                           | La instrucción posterior del usuario prevalece sobre «una fase por ejecución» del prompt.                                           |
| `productIds` de canje          | Son `Product.id`, no `RedeemableProduct.id`                                                                                                            | Permite seleccionar del catálogo y resolver el vínculo vigente en servidor.                                                         |
| Límite mensual                 | Mes calendario local Guayaquil                                                                                                                         | Supuesto solicitado expresamente por el prompt.                                                                                     |
| Lectura de catálogo del asesor | `GET /products` permite lectura filtrada a productos activos de su empresa, autorizada por `dice:create`; detalle y edición siguen solo ADMIN          | El asistente de dados debe elegir productos comprados, que no siempre son canjeables. Se usa una ruta existente, no una ruta nueva. |
| Identidad de datos mock        | Clientes por cédula; productos por SKU; canjeables/premios por `productId`; ventas por `productId`; lotes por UUID derivado de cédula/posición         | Los loaders son repetibles sin duplicar filas.                                                                                      |
| Formato de mock                | JSON con listas por dominio o CSV plano; `zoneNames` en CSV usa barra vertical como separador; clientes CSV repiten una fila por lote                  | Soporta archivos aportados por el usuario y un fixture sintético de respaldo.                                                       |
| Teselas del mapa               | Leaflet con OpenStreetMap                                                                                                                              | Mapa informativo; requiere acceso del navegador a teselas OSM para verse. No hace geolocalización.                                  |
| Contraseña temporal            | Aleatoria, mostrada una vez en la respuesta al ADMIN y nunca en auditoría                                                                              | No hay integración de envío de credenciales definida.                                                                               |
| Pruebas no ejecutadas          | Los tests de integración permanecen omitidos sin `RUN_DB_TESTS=1` y `club_test`; no se hizo prueba de navegador                                        | Respeta la elección del usuario y `agents/instructions_1.md`; no se presenta código no probado como validado.                       |
| reCAPTCHA en desarrollo        | Sin clave pública y en modo Vite desarrollo, el formulario envía `local-bypass`; el API solo lo acepta con `RECAPTCHA_BYPASS=true` fuera de producción | Permite una prueba local sin simular reCAPTCHA en producción.                                                                       |
